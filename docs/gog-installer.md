# Установка из офлайн-инсталлятора GOG (macOS)

Статус: 2026-10-18, ветка `launcher-gog-install` (от тега `v0.1-playable`). Работает на Mac, проверено на обоих русских инсталляторах GOG.

## Что видит игрок

1. В лончере у игры, которой нет на компьютере, кнопка **«Установить из GOG-инсталлятора…»**. В диалоге можно выбрать `setup_….exe`, его `…-1.bin`, оба сразу, несколько инсталляторов или папку, где они лежат. То же можно **перетащить на окно лончера** (а также папку установленной игры). «Папка игры…» тоже понимает папку с инсталляторами, если установленной игры в ней нет.
   - Поиск (`InstallerFinder` в `LauncherInstaller.swift`): в папке — `setup_*.exe` и `*-N.bin` на глубину до двух уровней; по `.bin` находится его `.exe` рядом; каждому `.exe` нужен `<имя>-1.bin` рядом. Найденные инсталляторы ставятся по очереди (по имени), ошибка или отмена останавливает очередь.
   - Папка, в которой уже есть установленная игра (или её `H5_Game.exe`), не ищется на инсталляторы: игра запускается на месте, как раньше.
   - Сообщения (ru/en): нет `…-1.bin` рядом с `…exe`; нет `…exe` рядом с `…-1.bin`; файл переименован браузером («`… (1)`», «copy», «копия») — с подсказкой, что во что переименовать; в папке нет инсталлятора и игры; выбранный файл — не инсталлятор.
2. Лончер узнаёт инсталлятор (GOG id), выбирает манифест, проверяет место на диске и распаковывает в `~/Library/Application Support/<приложение>/Games/<папка>`:
   - база + «Владыки Севера» (83649) → `Heroes of Might and Magic V`, 398 файлов, 4,08 ГБ;
   - «Повелители Орды» (83650) → `Heroes of Might and Magic V - Tribes of the East`, 356 файлов, 2,12 ГБ.
3. Окно прогресса: «Проверяем…» (уже распакованное), «Устанавливаем…» (файлы, байты, текущий файл), «Сверяем файлы…» (SHA-256). Кнопка «Отмена».
4. После сверки игра — «Готово», выбирается сама, «Играть» запускает её из установленной копии.
5. Прерванная установка (отмена, выход, падение, kill) оставляет в папке маркер `.recomp-install.json`. Игры этого инсталлятора показываются как **«Установка не закончена»**, главная кнопка — **«Продолжить установку»**: целые файлы остаются, недописанные и испорченные удаляются и распаковываются заново.
6. Повторная установка поверх готовой папки работает как «ремонт»: все файлы сверяются, испорченные заменяются.

## Как устроено

| Часть | Где |
|---|---|
| Инсталлятор: план (GOG id → `installers`, выбор манифеста по листингу), распаковка, сверка, маркер | `kit/host/launcher/apple/LauncherInstaller.swift` (новый, только macOS) |
| Модель: `pickInstaller`, `install(setup:)`, `resumeInstall`, состояние `.interrupted`, поиск маркера | `kit/host/launcher/apple/LauncherModel.swift` |
| Экран: `PrimaryButton` (Играть / Продолжить установку), кнопка установки, фазы и своя полоса прогресса | `kit/host/launcher/apple/LauncherView.swift` |
| Тексты ru/en | `kit/host/launcher/apple/LauncherStrings.swift` |
| innoextract 1.9: сборка, патчи, лицензии | `kit/third_party/innoextract/{build.sh,patches/,NOTICE.md}`, абзац в `kit/NOTICE` |
| Помощник и манифесты в бандле | `kit/tools/recomp/finish_bundle.py` → `Contents/Helpers/innoextract`, `Resources/launcher-manifests/`, `Resources/innoextract-NOTICE.md` |
| Конфиг | `launcher-games.json` → `installers` (id, gogId, folder, title, manifests, games) |
| Манифесты | `launcher-manifests/gog-1207661143-ru.json`, `gog-1207661193-ru.json` (путь, размер, SHA-256 — без содержимого игры) |
| Генератор манифестов | `tools/gen_install_manifest.py` |

Распаковка: innoextract запускается отдельным процессом с `--include /<путь>` для каждого нужного файла из манифеста (лишнее — `__redist`, `Editor*`, `tmp`, PDF, `commonappdata` — в манифест не входит по списку `exclude`). Прогресс — по размерам файлов на диске каждые 0,25 с, имя текущего файла — из вывода innoextract. Отмена — `terminate`. Если лончер умирает, innoextract получает SIGPIPE на следующем файле; PID помощника записан в маркер, и при возобновлении старый процесс останавливается, если ещё жив.

Манифесты сгенерированы из распакованных копий базовой игры и ToE; перед хешированием каждый файл сверен с MD5/SHA-1 из самого инсталлятора (`innoextract --list-checksums`) — все совпали. Повторить:

```sh
python3 -I tools/gen_install_manifest.py --installer "setup_….exe" --extracted "<распакованная копия>" --out launcher-manifests/gog-<gogId>-ru.json
```

Новая сборка инсталлятора (другой язык, ревизия GOG) — ещё один манифест в `manifests` того же `installers`-элемента; лончер берёт тот, все файлы которого есть в листинге.

### innoextract

- 1.9 с официального сайта (SHA-256 проверяется), три апстрим-патча (CMake 4, Boost 1.85, Boost 1.89 — те же, что в Homebrew).
- Boost 1.89 (BSL-1.0) и liblzma 5.8.1 (0BSD) — собираются из исходников (архивы с SHA-256, кэш в `build/innoextract/downloads`) под минимальную macOS приложения (14.0, `MACOSX_DEPLOYMENT_TARGET`) и линкуются статически; zlib, bzip2, libiconv — системные. Итог: ~850 КБ, зависит только от `/usr/lib` (build.sh это проверяет). Первая сборка — ~5 минут.
- Собирается один раз на дерево сборки (`build/innoextract/`) при упаковке бандла, если в игре есть `launcher-manifests/`, и заново, если `build.sh` новее готового помощника.
- Полные тексты лицензий: `kit/third_party/innoextract/NOTICE.md` (кладётся в бандл).

### Отладочные переключатели (новые)

| Переменная | Что делает |
|---|---|
| `RECOMP_LAUNCHER_INSTALL=<setup.exe>` | после первого поиска начинает установку из этого файла (автоигра ждёт её конца) |
| `RECOMP_LAUNCHER_INSTALL_CANCEL=<сек>` | отменяет её через столько секунд |
| `RECOMP_LAUNCHER_GAMES_DIR=<папка>` | вместо `Application Support/<app>/Games`; лончер ищет игры только там |
| `RECOMP_LAUNCHER_DUMP_DIR=<папка>`, `RECOMP_LAUNCHER_DUMP_EVERY=<сек>` | снимки лончера каждые N секунд |
| `RECOMP_LAUNCHER_LANG=ru\|en` | язык лончера |
| `RECOMP_INNOEXTRACT=<путь>` | другой innoextract вместо бандлового |

Сообщения лончера (алерты) теперь дублируются в stderr: `[launcher] …`.

Поиск инсталляторов (2026-10-19, без сборки) проверен тестовой обвязкой на локальных папках и APFS-клонах: папка с обоими инсталляторами, только `.bin`, `.exe`+`.bin`, два `.exe`, переименованные `.bin` и `.exe`, `.bin` без `.exe`, пустая папка, вложенность на два уровня, `H5_Game.exe`, посторонний файл; `GogInstaller.plan` (только `innoextract --gog-game-id`/`--list`) выбрал для обоих верные манифесты (398 и 356 файлов). Код лончера проходит `swiftc -typecheck` для macOS и iOS-симулятора. Живой сборкой ещё не проверены: диалог с папками и несколькими файлами, перетаскивание и подсветка окна, очередь из двух установок.

Не проверено руками: сам диалог выбора файла (`NSOpenPanel`) — тесты шли через `RECOMP_LAUNCHER_INSTALL`, который вызывает тот же `install(setup:)`. Клик по кнопке и выбор `.exe` стоит проверить вживую.

## Ограничения и дальше

- **iOS**: сделано (2026-10-19, ветка `ios-gog-install`), см. раздел ниже.
- **Распространение**: помощник собран под macOS 14+, как и приложение; `Contents/Helpers/innoextract` подписывается вместе с ним.
- **Песочница App Store** (если когда-нибудь): запуск помощника из бандла разрешён, но доступ к выбранному `.exe` и соседнему `.bin` потребует security-scoped bookmark на папку.
- Тестовые запуски пишут `launcher.roots`/`launcher.lastGame` в UserDefaults приложения (`io.github.hommare`), общие с основной сборкой.
- Пустые папки ToE из инсталлятора (`Maps`, `UserMODs`, `DuelPresets`…) innoextract кладёт под `app/` и в манифест не входят; при порте ToE проверить, создаёт ли их игра сама.

## iOS (2026-10-19, ветка `ios-gog-install`)

На iOS приложение не может запускать другие программы, поэтому innoextract встроен в приложение как статическая библиотека и работает в том же процессе.

**Игрок:** «Добавить файлы игры…» → в «Файлах» выбрать **оба** файла (`setup_….exe` и `…-1.bin`) или папку, где они лежат. Дальше — как на Mac: распознавание инсталлятора, распаковка в `Documents/Games/<папка>`, сверка SHA-256, «Готово». Папка с установленной игрой по-прежнему копируется. Если выбран только один из двух файлов — сообщение «выберите … вместе с … (отметьте оба файла) или папку»: «Файлы» дают приложению доступ только к выбранному.

| Часть | Где |
|---|---|
| Сборка библиотеки | `kit/third_party/innoextract/build-ios.sh <out> [iphoneos\|iphonesimulator]`: innoextract 1.9 + патчи Mac + `lib-patches/01-progress-hook.patch`, исходники Boost 1.89 (Filesystem, Iostreams) и liblzma (XZ 5.8.1, своим CMake), всё по SHA-256; `libtool` склеивает в `<out>/<sdk>/librecomp_innoextract.a` (~1,8 МБ, arm64). ~1 мин на SDK. |
| C-вход | `kit/third_party/innoextract/lib/recomp_innoextract.{h,cpp}`: `recomp_inno_gog_id`, `recomp_inno_list`, `recomp_inno_extract(setup, out, paths, n, progress, ctx)`; внутри — те же `extract_options`, что `main()` делает из аргументов помощника Mac, вывод innoextract читается построчно (имена файлов), stderr — текст ошибки, отмена — через хук в `progress::update` (патч). Вызовы сериализованы мьютексом. |
| Подключение | `kit/host/CMakeLists.txt`: на iOS при конфигурации собирает библиотеку в `build/innoextract-ios/` (если её нет; опция `RECOMP_IOS_INNOEXTRACT`, по умолчанию ON), линкует к `launcher_native` (+ `z bz2 iconv`) и ставит Swift-флаг `RECOMP_INNOEXTRACT_LIB`. Без библиотеки лончер, как раньше, говорит распаковать на Mac. Модуль `RecompInnoextract` — в `RecompSettings/module.modulemap`. |
| Бандл | `kit/cmake/IosBundle.cmake`: `launcher-manifests/` и `innoextract-NOTICE.md` (раньше в iOS-бандл не попадали). |
| Swift | `LauncherInstaller.swift`: `GogInstaller` общий для Mac и iOS (`#if os(macOS) \|\| RECOMP_INNOEXTRACT_LIB`); путь Mac (помощник, `--include`, PID в маркере) не менялся, только вынесены `gogId`/`listing`. `LauncherModel.swift`: `usePicked` → `installFound` → та же очередь `installNext`/`install(setup:)`; security-scoped доступ к выбранному держится, пока идёт очередь; закладки (`bookmarkData`) на выбранное пишутся в маркер (`access`), «Продолжить установку» после перезапуска открывает их снова. Перед распаковкой `NSFileCoordinator` докачивает файлы из iCloud Drive/провайдера. |

**Приложение без игры.** `tools/build.py --target ios … --no-game-files` (CMake `RECOMP_BUNDLE_GAME=OFF`) не кладёт в бандл `game/` (у базовой сборки это 3,8 ГБ из 4,8 ГБ); если папка осталась от прошлой сборки в том же дереве, она удаляется. HoF и ToE и раньше приходили модулями без своих файлов. Игрок ставит все три игры на телефоне из GOG-инсталляторов (или копирует папку установленной игры). Без флага сборка по-прежнему несёт игру разработчика и импортирует её при первом запуске. Ещё не собиралось и не проверялось (2026-10-20).

**Регистр имён.** Файловая система iOS различает `Data` и `data` (симулятор это эмулирует: `stat("Data")` — нет, `mkdir("Data")` — «уже есть»). innoextract пишет папку так, как она названа у первого распаковываемого в неё файла, и при возобновлении (другой набор файлов) выбирал другое написание: возобновление падало «Could not create directory …/Data», на устройстве игра разъехалась бы на две папки. Поэтому на iOS innoextract распаковывает в пустую `<папка игры>/.recomp-unpack/`, а потом каждый файл переносится на путь из манифеста через уже существующие папки без учёта регистра (`GogInstaller.adoptStaged`). Недописанные файлы тоже переносятся — следующая проверка найдёт их короткими и распакует заново.

**Проверено** (симулятор iPhone 18 Pro Max, iOS 27.0, тестовая обвязка = Swift-файлы лончера + библиотека, без игры):

| Проверка | Результат |
|---|---|
| CLI в симуляторе: GOG id, листинг (2071 путь), распаковка 3 файлов, отмена на 50 МБ, нет файла, не Inno Setup | всё как у помощника, SHA-256 совпали |
| «Файлы» → «На iPhone»/GOG → оба файла → Open | база+HoF: 398 файлов, ~20 с, «Готово», «Играть» активна |
| Только `.exe` | сообщение «выберите …-1.bin вместе с …exe» |
| ToE с нуля | 356 файлов, 14–18 с, все SHA-256 совпали (проверено отдельно Python'ом) |
| Отмена через 8 с → перезапуск → «Продолжить установку» (через закладки) | 32 файла распакованы заново, 398/398 SHA-256 совпали, дублей папок по регистру нет, `.recomp-unpack` и маркер убраны |

**Не проверено:** настоящее устройство (там доступ к файлам действительно ограничен песочницей — в симуляторе нет), iCloud Drive с невыкачанными файлами, полная сборка iOS-приложения с изменённым CMake (Xcode-генератор: линковка `.a` к Swift-библиотеке и `SWIFT_ACTIVE_COMPILATION_CONDITIONS`), место на диске при 4 ГБ на телефоне (проверка свободного места та же, что на Mac).

## Приложение без данных игры (2026-10-21, ветка `ios-gog-install` после слияния `integrate` c1f0174)

Одно приложение HommaRe с модулями HoF и ToE, в котором нет ни файлов игры, ни модов, собранных из её данных. Лончер ставит все три игры из офлайн-инсталляторов GOG игрока (на Mac — помощник `Contents/Helpers/innoextract`, на iOS — библиотека, Swift-флаг `RECOMP_INNOEXTRACT_LIB`; манифесты `launcher-manifests/*.json` — только пути, размеры и SHA-256). Моды интерфейса делаются при запуске игры из рецептов (`docs/ui-mods.md`): на Mac — широкий экран для всех трёх игр, на iOS — ещё TouchUI, MobileOptions и PhoneUI на iPhone.

**Собрать** (нужны трансляции трёх игр в `build/recomp`, `games/{hof,toe}/build/recomp`, как для любой сборки):

```sh
.venv/bin/python tools/build_app.py --target app        # Mac: build/HommaRe.app
.venv/bin/python tools/build_app.py --target ios-sim    # симулятор
RECOMP_IOS_TEAM=<team> .venv/bin/python tools/build_app.py --target ios   # устройство
```

`build_app.py` собирает базу, HoF и ToE через `kit/tools/build.py --game-modules --no-game-files --no-install --release`, переносит модули дополнений в приложение базы (`kit/tools/assemble_games.py`) и проверяет результат. iOS-приложение ставится `xcrun devicectl device install app --device <id> <app>` (симулятор: `xcrun simctl install <udid> <app>`).

**Релизная сборка.** `--release` у `kit/tools/build.py` (CMake `RECOMP_RELEASE=ON`) убирает старый виджет производительности кита: счётчики и график времени кадра (F11). Строки «performance_overlay» нет в настройках, сохранённое значение не действует, F11 ничего не делает (`kit/mods/display_settings.cpp`). Metal HUD в лончере остаётся. `build_app.py` собирает так по умолчанию; `--overlay` оставляет виджет для проверок. Флаг пишется в CMake всегда, ON или OFF, чтобы кэш не помнил прошлую сборку.

**Проверить, что в бандле нет данных игры:**

```sh
.venv/bin/python tools/check_bundle.py build/HommaRe.app --game ~/Heroes\ V/game --game ~/Heroes\ V/game-toe
```

Скрипт обходит бандл (и записи всех zip в нём) и падает на: файлах тех видов, что у игры (`.pak .h5u .h5m .h5c .h5s .xdb .dds .tga .bik .exe .dll .bin …`), папках `game/` и `profile-seed/`, любом zip (мод — это zip), картинке, которой нет среди файлов репозитория, строке рецепта, которая не раскладка интерфейса; с `--game` — ещё на любом файле или записи zip, чьи байты совпадают с файлом установки или записью её паков (по размеру и CRC-32 из каталогов паков, затем побайтно; файлы меньше 64 байт сравниваются только по виду). Без провала выводит заметки об арте из репозитория, который показывает приложение: `AppIcon.icns` (из `icon.png`) и `launcher-splash.jpg` — это не файлы игры, но на них логотип Heroes V.

`RECOMP_LAUNCHER_INSTALL` теперь принимает и папку, и несколько путей через `:` — то же, что выбор в диалоге.

## Установка из библиотеки GOG.com (2026-10-29, ветка `gog-direct-download`)

**Зачем.** На iOS выбор инсталлятора в «Файлах» у части игроков не работает (IPA, переподписанный LiveContainer/подписчиками, ломает document picker; файлы в облачном провайдере), а перенос 2+ ГБ на телефон сам по себе неудобен. Теперь главная кнопка неустановленной игры «Установить из GOG…» открывает панель GOG.com (`LauncherGogView.swift`): вход на странице GOG → приложение проверяет, что игра есть в библиотеке аккаунта, и скачивает файлы сборки GOG Galaxy (generation 2) прямо в папку игр (iOS `Documents/Games/<folder>`, Mac `Application Support/<app>/Games/<folder>`). «Использовать файлы инсталлятора…» в той же панели — прежний путь (Mac — выбор инсталлятора, iOS — «Файлы»): для владельцев Steam/диска и для тех, у кого инсталляторы уже есть. Работает и на Mac.

**Как устроено** (`LauncherGog.swift`; вход, токены, подписанные ссылки CDN и чанки — порт `shim/StoresCore.swift` из CyPort, MIT © Thijs Mussig, лицензия в шапке файла):
- Вход: `WKWebView` (без сохранения cookies, `.nonPersistent()`) на `auth.gog.com/auth` с публичным клиентом GOG Galaxy; код перехватывается на `embed.gog.com/on_login_success` и меняется на токены. Токены — в Связке ключей (`<bundle id>.gog`, `AfterFirstUnlockThisDeviceOnly`), обновляются за 5 минут до истечения; отказ GOG (4xx) на обновлении = выход. Если у приложения нет группы Связки ключей (неподписанная сборка симулятора `CODE_SIGNING_ALLOWED=NO`, некоторые подписчики), вход держится в памяти до конца запуска (в лог: `gog: no keychain (-34018)`). Владение — `embed.gog.com/user/data/games`.
- Сборка: `launcher-games.json` → `installers[].gogBuild` закрепляет ту же сборку, из которой сделаны манифесты (база 58812465975493914 «2.1 v3 GOG», ToE 58812602200645111 «3.1 v3 GOG»); без него — самая новая. Список сборок и описания депо публичные (без входа); депо выбираются по языку игры (`*` + язык; языки лончера → коды GOG: en→en-US … zh-Hans→zh-Hans), более поздний депо перекрывает общий.
- Что кладётся: файлы депо минус `exclude` из `launcher-games.json` — ровно набор манифеста (проверено для base/ToE × en/ru: совпадают пути и размеры; в депо нет только `app/*` — служебных файлов офлайн-инсталлятора Galaxy, они не нужны). Есть манифест языка (`gog-<id>-<lang>.json`) — пути пишутся как в манифесте, каждый файл сверяется с его SHA-256, а недостающий/другого размера файл манифеста (кроме `app/`) — ошибка до загрузки. Меню «Язык игры» предлагает только языки, для которых у каждого инсталлятора есть манифест (`LauncherModel.gogLanguages`; сейчас en, ru, de, fr, pl) — новые появятся сами с манифестами. Загрузчик умеет и языки без манифеста (cs es it hu zh-Hans: проверка только по MD5 GOG; `H5_Game.exe` во всех языках один, проверка exe в `Detector.probe` их пропустила бы), но они не проверены и в меню не показываются. Папки сводятся без учёта регистра (`GogDownloader.place`, как у innoextract на iOS): депо ru пишет `Bin/`, `Data/`.
- Загрузка (`GogDownloader.run`): пометка `.recomp-install.json` с `gog: {product, build, language}` и `setup: "GOG.com"` → «Установка не закончена», «Продолжить установку» качает дальше (`resumeInstall` → `downloadFromGog(source:)`). Проверка того, что уже есть: целые чанки с MD5 GOG подряд (и SHA-256 этого начала); файл дописывается с первого несошедшегося чанка. 8 чанков качаются вперёд параллельно, пишутся по порядку; каждый чанк сверяется по MD5 сжатого и распакованного, до 5 попыток со сменой ссылки. Прогресс — тот же `ImportProgress` (новая фаза `.downloading`), отмена — та же кнопка. Место проверяется до загрузки, папка на iOS исключена из резервной копии.
